## P2（记录在案，不阻塞）

1. **`/admin/api/sessions` 在事件循环里同步读 1GB sqlite** — admin_api.py:1089。
   实测真实库查询 126ms（session 表无 time_updated 索引，328 行排序 + message 计数 7ms）。
   每次调用都在 SSE 流转发的同一循环里卡 100ms+。同文件 `admin_burner.py:62` 对同类场景
   已用 `asyncio.to_thread`，此处应保持一致。
2. **半开探测节流是进程级全局，不分 provider** — gateway.py:720 `_last_pool_probe`。
   zai 与 bigmodel 共享同一窗口：一侧探测会把另一侧的探测推迟最多 30s。单 provider 部署无影响；
   双 provider 且都全池冷却时恢复变慢。
3. **探测判定靠错误文案字符串耦合** — gateway.py:742 `"上游 HTTP 5" in a.last_error`。
   上游错误文案在别处改动会让探测静默失效（退化为「硬等满 COOLING_SECONDS」的旧行为，不算事故）。
   建议在账号上记结构化的 `last_fail_kind`。
4. **探测失败后的 503 ETA 虚高** — gateway.py:701-704。探测号重新冷却后 `min(cooling_until)`
   回到满额 COOLING_SECONDS，文案说「约 300s 后恢复」而下一个探测窗口是 30s。
5. **插件版本目录按字符串排序取「最新」** — admin_api.py:1077 `sorted(..., key=p.name)`。
   `0.10.0` < `0.2.0`（字典序），插件升到 0.10+ 会指错 hook 路径。当前 0.1.0 无影响。
6. **supervisor.html 轮询覆盖失焦草稿** — frontend/admin/supervisor.html:174-190。
   一次性指令 textarea 仅在聚焦时保留草稿；输入后点别处（失焦未保存），5s 轮询会用服务端值覆盖。
   白名单框有 `_projectsLoaded` 门禁，指令框没有等价物。
7. **`_pending_grant_hint` 文案只有时刻没有日期** — app/claim.py:380。
   `effective_at` 在明天时显示「将于 23:00 生效」有歧义，建议 `%m-%d %H:%M`。
8. **stop-all.ps1 匹配过宽** — scripts/stop-all.ps1:27-33。凡命令行含 `supervisor.py`/`cli.py serve`
   的 python 都会被停（含其他项目同名脚本）；且优雅停服 Key 默认 `zcode`，改过后台密码时
   graceful 路径必然失效、走强杀。可按仓库路径过滤 + 从 data 里读实际 key。
9. **`test_state_survives_reload` 实际未换环境** — tests/unit/test_burner.py:181-193。
   monkeypatch 把 QUEUE_FILE 设成它自己（注释也承认"路径未变"），断言的只是 snapshot 读盘，
   没有验证"新进程从磁盘恢复"的本意。建议 mock 重建模块级常量后断言行为不变。

## 发版摘要（v2.16.0，可直接用于 release notes）

**流式可靠性**
- 上游 SSE 中途断连且尚未向客户端输出任何内容时，网关自动重新调度（可换号/换连接/重过验证码），
  客户端无感（默认重试 2 次，`ZCODE_STREAM_RETRY_TIMES` 可调）。
- 已有内容输出的中断不再重放（避免重复正文），改发标准 `event: error` 帧（Anthropic）或
  error chunk（OpenAI）显式收口，客户端能识别「回答不完整」。

**池可用性**
- 全部账号因上游 5xx 冷却时，每 30s（`ZCODE_COOLING_PROBE_INTERVAL`）半开放行一个真实请求探测，
  上游恢复后 ~30s 内自动解冻，不再硬等满 300s 冷却。风控/人工冷却绝不绕过。
- 全池无可用账号时 503 文案给出具体原因（冷却中+恢复 ETA / 额度耗尽 / 凭证失效 / 无启用账号），
  不再是笼统的「无可用账号」。

**额度与领取**
- `billing/current` 与 `billing/balance` 的套餐按 plan_id 合并（balance 字段优先）：修复
  「领取成功后 current 置空 → 后台显示无套餐、赠送池判定失效」的问题。
- 一次性赠送授权增加套餐级门禁：status 非 active 或套餐窗口已结束的残留套餐不再把账号撑成可用。
- preview 为空但存在待生效赠送时，领取提示改为「已领取，将于 HH:MM 生效」，不再误导为失败。

**运维与停服**
- 新增 `/admin/api/shutdown` 优雅停服（drain 在飞请求）；`scripts/stop-all.ps1` 与
  restart 脚本改为「先停守护 → 优雅 drain → 兜底强杀」，客户端不再看到 mid-reply 断连。
- 守护进程检测端口已被占用时直接退出，不再无限退避重试刷 crash 日志。

**续派工单（zburn-hub 合并）**
- 工单队列/派单/验收状态机并入 `app/burner.py`，随网关启停；后台新增「续派工单」页
  （链路状态、总闸/循环/一次性指令、项目白名单、会话监听、工单 CRUD、Stop 钩子日志）。
- 新增会话监控：只读 ZCode 本地库列出最近对话，可勾选监听名单（`continue.sessions`）。

**界面**
- 设置页瀑布流重排（≥1180px 双列、整卡不拆），续派监督卡迁至独立页，导航新增入口。

**质量**
- 全量测试 621 通过；新增流中断重试（mock 真实断连）、工单状态机、池原因文案、
  优雅停服、会话库只读等 19 个用例。
